#+title: dotfiles

My desktop on Arch Linux: X11 with the i3 window manager, kitty as the
terminal, Emacs as the editor and qutebrowser as the browser. Everything
is themed together.

* The idea

** Keyboard first, few moving parts
i3 tiles the windows, and rofi is the one menu for everything: launching
programs, picking a color scheme or a font, and looking up key bindings.
A dropdown terminal is always a key away. The bar is bumblebee-status,
redrawn by a small script so it fits the rest of the desktop. Every
program is set up to be driven from the keyboard.

** One look, everywhere
There's one color scheme and one monospace font for the whole system.
Switching either one changes kitty, the shell prompt, i3 and its bar,
rofi, qutebrowser (and claude.ai, x.com, Wikipedia, YouTube and GitHub in it),
Emacs, Discord (Vesktop) and the lock screen together, and each program reloads by
itself. Nothing needs restarting.

- =theme-select= picks any base16/base24 scheme. [[https://github.com/tinted-theming/tinty][tinty]] keeps track of
  the schemes and which one is in use.
- =font-select= picks any installed monospace font. Each program keeps
  its own font size.

Each program's colors come from a template in
=tinty/.config/tinted-theming/templates/=. When a scheme is applied,
=apply-scheme= fills in the templates and reloads the programs. First it
checks the scheme for readability (WCAG contrast ratios) and makes small
lightness adjustments where text wouldn't read. Hue is never changed, so
even a loosely made scheme stays legible, and well-made schemes are left
exactly as they are.

** Restyling websites (and Discord)
The scheme also goes into a few websites in qutebrowser, and into
Discord. None of these sites support outside themes, so each one is
restyled by overriding its own CSS from outside. There's one template
per site in =tinty/.config/tinted-theming/templates/=, and each site
gets whichever approach suits how it's built:

| Site      | Template            | How it's restyled                                                         |
|-----------+---------------------+---------------------------------------------------------------------------|
| claude.ai | =claude.css=        | a qutebrowser user stylesheet that overrides its design-system variables (=--cds-gray-*= and the role scales), plus the fixed colors of its newer look |
| Wikipedia | =wikipedia.user.js= | a greasemonkey script that sets Codex's design-token variables and switches the page to night mode |
| x.com     | =x.user.js=         | a greasemonkey script that matches X's generated class names (=.r-kemksi=) and inline styles, since X has no color variables |
| YouTube   | =youtube.user.js=   | a greasemonkey script: a stylesheet for the variables with readable names, and then =recolor.js= for the rest |
| GitHub    | =github.user.js=    | a greasemonkey script that uses =recolor.js= on Primer's "Dark default" theme variables |
| Discord   | =discord.css=       | a Vesktop theme that overrides Discord's color variables. =vesktop/.../quickCss.css= flattens the layout |

=recolor.js= is shared by YouTube and GitHub. Those sites have too many
color variables to list by hand (GitHub has about a thousand, and most of
YouTube's have scrambled names), so the script reads the site's own
dark-theme variables from its stylesheets while the page loads, whatever
they're called. It maps each gray to a scheme shade by lightness and each
color to the accent nearest in hue.

=apply-scheme= writes the stylesheet and scripts, runs
=:config-source= and =:greasemonkey-reload= in qutebrowser, and then
reloads every open tab (=reload-tabs.py=), since the styles only apply
when a page loads. Each themed page sets =color-scheme: dark=, which tells
qutebrowser's built-in darkmode to leave it alone. Every other site still
gets the generic darkmode.

Some site settings have to stay a certain way, because only the site's
dark theme is themed:
- claude.ai: set the appearance to Dark.
- x.com: set the display to "Lights out".
- YouTube: set the appearance to Dark, or to "Use device theme".
- GitHub: keep the dark theme on "Dark default".
- Wikipedia: the script picks dark mode itself, overriding Appearance.

*** Warning: this will break
All of this depends on the sites' internal CSS: variable names, class
names, which attribute marks the dark theme, and what their stylesheets
look like. None of that is a public interface. The sites change it
without notice, sometimes several times a month, and *a site update can
undo some or all of the theming at any time*. Nothing here notices when
that happens. There's no error. Part of the page just goes back to the
site's own colors, or, worse, gets the scheme's background without the
matching text color, and becomes hard to read.

How likely each one is to break, roughly from most to least likely:
- x.com: its class names are generated and get renamed with new
  releases. The names come from [[https://github.com/catppuccin/userstyles][Catppuccin's userstyles]], which are
  kept up to date and are the first place to look for new ones.
- Discord: its variable names changed completely in the 2025 redesign,
  and the hashed class suffixes (=sidebar_pog62O=) change with updates.
  =quickCss.css= only matches the stable start of a class name for this
  reason, but a redesign will still break it.
- claude.ai: its design system is under active development. The newer
  look already replaced many variables with fixed values, and more may
  follow.
- YouTube: most of its variables have scrambled names that can change with
  every release. =recolor.js= doesn't depend on those names, but it does
  depend on the =html[dark]= attribute and on the stylesheets being
  readable, and the named variables and classes in the template can
  still change.
- GitHub: Primer is versioned and fairly stable, but the match relies on
  the =data-dark-theme="dark"= selector and on GitHub's grays staying
  near the lightness values in the template's ramp.
- Wikipedia: Codex tokens are documented and change slowly, but
  =skin-theme-clientpref-night= and the article template colors are
  not guaranteed either.

When a site looks wrong after an update:
1. Open the page's inspector (=:devtools= in qutebrowser) and find the
   element that has the wrong color.
2. Find the variable or class that colors it now, and add it to that
   site's template next to the old one. Keep the old one in case the
   change is rolled back.
3. Run =theme-select= again (or reapply the current scheme) to write the
   files out and reload the tabs.

If a site can't be fixed quickly, remove its line from =APPS= in
=apply-scheme= and delete the file it wrote. For claude.ai, that's
=~/.config/qutebrowser/claude.css=; for the others, it's the matching
=base16-*.user.js= in =~/.local/share/qutebrowser/greasemonkey/=. That
site goes back to qutebrowser's generic darkmode. For Discord, untick
=base16-tinty.css= in Vesktop's Themes settings.

** Emacs as the workbench
The Emacs config (=emacs/.config/emacs/=) is split by topic: completion,
editing (evil, vim-style), git (magit and forge), C (clangd through
eglot, with tree-sitter), Org, and LaTeX with a live PDF preview. It
runs as a daemon started by i3, so new windows open instantly. Its own
[[file:emacs/.config/emacs/README.org][README]] covers how to use it.

** Extras
- =$mod+Escape= locks the screen. =blur-lock= shows =i3lock-color= over a
  pixelated screenshot, with a small, thin ring in the scheme's colors.
  It runs through =xss-lock=, so locking before suspend looks the same.
- An Onyx Boox e-ink tablet works as a second screen. =boox-screen=
  mirrors it with scrcpy over USB or Wi-Fi, and picom recolors it in the
  color scheme: paper as the background, ink as the text color.
  =boox-ink= draws pen strokes over the mirror while they're drawn,
  since Boox Notes only hands them to the screen on pen-up.
- Kitty's scrollback opens in Neovim, so it can be searched and copied
  like a file.

* Layout
Each top-level directory is a [[https://www.gnu.org/software/stow/][GNU Stow]] package and mirrors where its
files go in =~=:

| Directory     | What's in it                                                        |
|---------------+---------------------------------------------------------------------|
| =x11=         | =.xinitrc=: starts i3                                               |
| =i3=          | the window manager, and the keyboard remap (=xmodmap=)              |
| =bumblebee=   | the status bar, and the script that lays it out                     |
| =kitty=       | the terminal, its kittens, and the Neovim scrollback pager          |
| =zsh=         | shell and the powerlevel10k prompt                                  |
| =rofi=        | the menu's layout                                                   |
| =picom=       | the compositor                                                      |
| =qutebrowser= | the browser                                                         |
| =vesktop=     | Discord: its launcher (named Discord in rofi) and the QuickCSS that flattens it |
| =emacs=       | the editor                                                          |
| =tinty=       | the color scheme and font pipeline: tinty's config, =apply-scheme=, the templates |
| =bin=         | scripts in =~/.local/bin=: =theme-select=, =font-select=, =i3-keys=, =boox-screen=, =boox-ink=, =blur-lock=, ... |

Stow runs with =--no-folding= (see =.stowrc=), so it links individual
files and never whole directories. Directories like =~/.config/kitty=
stay real, and the files written at runtime (each program's current
theme, Emacs's packages and caches) land there instead of in the repo.
=.gitignore= is a backup in case one ever ends up in the repo anyway.

* Installation
Start from an Arch Linux install with a user that can use =sudo=.

** 1. Clone the repo
Clone it into your home directory:
#+begin_src sh
git clone https://github.com/9ziggy9/arch-dotfiles.git ~/dotfiles
cd ~/dotfiles
#+end_src

** 2. Run the bootstrap script
#+begin_src sh
./bootstrap.sh
#+end_src
It updates the system, then:
- installs the packages from the official repos (pacman)
- installs =paru= if needed, and the AUR packages: =bumblebee-status=,
  =tdrop=, =zsh-theme-powerlevel10k=, =vesktop-bin= and =i3lock-color=
  (paru asks to remove =i3lock= if it's installed: say yes)
- sets up Rust and runs =cargo install tinty=
- stows every package into =~=

It's safe to run again: anything already installed is skipped. If a
file in =~= is in the way of a link, stowing stops before changing
anything and lists the conflicts. Move those files aside and run it
again. To install the packages without stowing, use
=./bootstrap.sh --no-stow=.

** 3. Finish up by hand
The script prints these steps at the end:
- make zsh your shell: =chsh -s /usr/bin/zsh=
- enable NetworkManager if you use it:
  =sudo systemctl enable --now NetworkManager=
- for GitHub from Emacs: =gh auth login=, and a token in =~/.authinfo=
  for forge
- in Vesktop, once: Settings → Themes, tick =base16-tinty.css=; and
  Settings → Plugins, turn on KeepCurrentChannel, so it opens on your
  last channel instead of the Quests page

** 4. Start the desktop
Log in and run =startx=. On the first start, i3 applies the default
color scheme (Solarized Dark), and every program gets its theme.
Emacs downloads its packages the first time it runs. The first time
it opens a PDF, it offers to build pdf-tools' helper: accept.

** Notes
- This setup is X11 only: i3, picom, xmodmap and tdrop don't run on
  Wayland.
- The Insert key is remapped to a modifier (Hyper) for kitty shortcuts.
  =i3/.config/i3/insert-hyper.xmodmap= explains why and how to undo it.
- =kitty.conf= points at the scrollback pager through an absolute path
  in my home directory. Change it if your username is different.
